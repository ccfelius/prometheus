Click a column heading to sort. CPU bars compare CPU nanoseconds per complete input sample within the current selection. Lower time, CPU cost, and stored size are better; higher throughput is better. The ratio column uses raw numeric payload divided by encoded size, including encoded headers and timestamps.

Histogram samples are whole snapshots, not individual buckets. Allocation figures are per input batch. Reset and layout cases can produce multiple chunks per batch. Fresh-iterator scans do not flush caches or access disk. Adaptive compaction reuses an encoder for repeated chunks from one homogeneous series.

CPU percentage is relative to one core. Similar utilization does not imply similar CPU cost. These results do not measure end-to-end ingestion, PromQL, multi-core scaling, or production workload frequency.
